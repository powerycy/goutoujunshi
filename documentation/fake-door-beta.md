# 狗头军师新人限定免费内测规格

> 版本：2026-07-21（最终产品规则）。适用于尚未接入微信虚拟支付的免费封闭内测。当前页面可以展示正式计划价格，但必须明确说明暂不可付款，不发起支付、不收款。

## 一、决定

正式支付接入前，只展示新人限定方案 `¥1/10 狗头`。用户点击后，系统立即说明当前无法付款、没有唤起微信支付、没有扣款；前 10,000 名去重用户登记为 `founding_beta_2026` 创始内测官。

创始内测权益分成两个互不混淆的层次：

1. **免费分析**：以稳定服务端 `user_id` 为准，前 10,000 名每人获得 2 次免费完整关系分析。
2. **正式版活动额度**：同一批创始内测官在正式版获得 10 个活动狗头，自实际发放之日起 60 天有效，不要求先购买，不可提现、转赠或折现。权益版本为 `launch_credit_10_60d_v1`。

第 10,001 名及以后只记录一次新人方案点击，不登记创始内测身份、不发免费分析，也不预留正式版活动狗头。

页面不得展示支付成功动画、微信支付订单号、虚构到账记录或任何真实支付 SDK。

## 二、用户流程与文案

### 2.1 价格页

标题：

> 开始第一次关系问题分析

说明：

> 先解决一个最急的关系问题。每次成功交付完整分析扣 1–3 狗头；没有交付，不扣狗头。详细用量规则可展开查看。

方案：

- `新人限定｜10 狗头｜¥1`，按钮：`开始新人分析`

价格页明确写明“当前尚未接入支付，点击不会扣款”；点击后再次展示 ¥0 回执，避免任何误解。

### 2.2 首次点击：前 10,000 名

标题：

> 当前免费，正式版权益已预留

正文：

> 当前尚未接入正式支付——本次没有唤起微信支付，也没有扣款。
>
> 你已成为「创始内测官」，并进入前 10,000 名：
>
> - 当前 2 次免费完整关系分析；
> - 正式版 10 个活动狗头，自实际发放日起 60 天有效；
> - 当前没有发生任何付款。

### 2.3 首次点击：第 10,001 名及以后

标题：

> 本轮内测名额已满

正文：

> 本次没有唤起微信支付，也没有扣款。当前内测名额已经领完，本次只记录价格点击，不发免费分析或正式版活动狗头。

当前免费内测阶段不接真实支付，可显示候补提示或返回首页；不能让名额外普通用户调用模型。

### 2.4 已登记用户再次点击

标题：

> 你的内测权益已经登记

正文：

> 你的「创始内测官」身份、免费分析次数和正式版 10 个活动狗头已经记好。本次仍未发生支付，也不会重复领取免费次数或占用新名额。

### 2.5 免费分析核销

只有服务端将任务更新为 `delivered`、完整结构化结果通过输出安全检查并与核销处于同一事务时，才消耗 1 次免费分析：

> 本次使用 1 次免费完整分析，扣款 0 元。只有成功交付结构化分析报告后才核销。

模型超时、系统错误、JSON 修复失败、输出被安全层拦截、危机场景转介或没有交付可用分析时不核销。创建任务时先原子预留一次，失败时释放预留，避免双设备并发超发。

## 三、产品与数据规则

### 3.1 免费名额与一次完整分析

- `beta_campaigns` 中 `campaign_key=founding_beta_2026`、`quota_total=10000`，`claimed_count` 只统计获得 2 次免费分析的去重用户。
- 首次有效假门点击在服务端 `BEGIN IMMEDIATE`/等价事务中条件增加 `claimed_count`。第 10,000/10,001 名并发时，只有一人获得免费次数。
- 每个稳定服务端 `user_id` 在 `beta_cohort_members` 中唯一；清理小程序缓存、双击或换设备不重复领取。
- 一次完整分析至少包含情绪确认、事实/推测/未知、核心判断、下一步行动、观察窗口和停止条件。
- 单次模型请求的服务端硬上限为最多 3 狗头对应的 30,000 成本折算 Token；超限不交付、不核销。
- 阶跃 `step-3.5-flash` 标准 6,000 未缓存输入 + 1,000 输出约 ¥0.0063/次；10,000 次标准模型调用约 ¥63。前 10,000 名若把 2 次全部用完，最多 20,000 次标准调用，模型成本基准约 ¥126；均不含服务器、审核和异常重试。

### 3.2 数据表

`beta_campaigns`：

| 字段 | 说明 |
| --- | --- |
| `campaign_key` | 固定 `founding_beta_2026` |
| `quota_total` | 固定 10,000 |
| `claimed_count` | 已获得免费分析资格的去重用户数，事务条件更新 |

`beta_cohort_members`：

| 字段 | 说明 |
| --- | --- |
| `user_id` | 稳定服务端用户 ID，唯一索引 |
| `cohort` | 固定 `founding_beta_2026` |
| `joined_at` | 首次有效假门点击时间 |
| `selected_package` | 固定 `cny_1` |
| `trial_analysis_total` | 固定 2 |
| `trial_analysis_used` | 仅 `delivered` 后增加 |
| `trial_analysis_reserved` | 处理中原子预留；失败/拦截时释放 |
| `benefit_version` | 固定 `launch_credit_10_60d_v1` |
| `benefit_status` | `reserved`、`active`、`ended` |
| `source_event_id` | 首次假门事件，唯一 |

免费分析资格、内测身份和正式版活动额度属于同一批前 10,000 名用户，但当前免费次数与未来活动狗头仍需分账表达。

### 3.3 API 返回

`GET /v1/beta/me` 与 `POST /v1/beta/purchase-intents` 至少返回：

```json
{
  "eligible": true,
  "freeAnalysisEligible": true,
  "remainingSlots": 9999,
  "trialAnalysisTotal": 2,
  "trialAnalysisRemaining": 2,
  "benefitVersion": "launch_credit_10_60d_v1",
  "launchBonusCoins": 10,
  "launchBonusValidityDays": 60,
  "paymentInvoked": false
}
```

`remainingSlots` 可近似展示；资格判定始终以事务结果为准。第 10,001 名以后 `eligible=false`、`freeAnalysisEligible=false`、`trialAnalysisTotal=0`。

### 3.4 埋点

至少记录：`pricing_viewed`、`package_clicked`、`beta_enrolled`、`beta_reward_viewed`、`trial_analysis_started`、`trial_analysis_completed`、`returned_day_1`、`returned_day_7`。

不得把问题正文、真实姓名或第三人联系方式写入埋点。`package_clicked` 不能命名为 `payment_success`，也不能当真实付费转化率。

## 四、正式上线后的 10 个活动狗头

所有 `founding_beta_2026` 用户均享受：

1. 正式版活动启用时，一次性发放 10 个活动狗头，不要求用户先购买。
2. 活动狗头自实际到账时间起 60 天有效，界面显示明确到期日。
3. 正式接入时使用微信官方代币赠送能力；赠送单号全局唯一并幂等。
4. 账本以 `PROMO_BONUS` 单独记录，不能提现、转赠、折现或退款。
5. 当前免费阶段不得调用任何支付或代币赠送接口。

## 五、验收用例

- 首次点击新人限定：未唤起支付，立即说明未扣款；有名额时登记内测身份。
- 第 10,000/10,001 名用两个独立数据库连接并发领取：只有一人登记 `founding_beta_2026`、获得 2 次免费分析和 `launch_credit_10_60d_v1`，另一人只保留价格点击记录。
- 同一用户连续点击、双击、换设备点击：意愿均可记录，但成员只有一条，免费次数不增加，配额只占一次。
- 两次免费分析并发创建时各预留一次；第三次不能超额创建。
- `delivered` 才把预留转成已使用；模型失败、超时、安全拦截或危机转介释放预留。
- 名额外用户可看到候补/售罄文案，不能在当前免费阶段调用模型。
- 埋点不存在支付成功、实收金额、微信订单号或问题正文。
